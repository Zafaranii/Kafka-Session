Synchronous, Request-Driven

What's happening: this stops ws-service, which holds every browser WebSocket connection entirely in memory — there is no queue or durable store behind it. notify-api retries its push to ws-service a few times with backoff, but once those retries are exhausted the notification is gone for good. Restarting ws-service afterwards does not recover it — send a notification now and watch it fail.

Event-Driven, Asynchronous

What's happening: this stops the notifier-consumer container while Kafka keeps accepting events from producer-api. Because notifier-consumer commits its offset to Kafka under a fixed consumer group, no message is lost — delivery is only delayed. Send a notification now, then restart it: the notification still arrives, just late.
